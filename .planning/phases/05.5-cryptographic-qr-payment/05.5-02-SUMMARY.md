## Architecture Changes

### File Split for Convex Runtime Compatibility
The original `cryptographicQr.ts` had mixed runtime requirements:
- Split into `cryptographicQr.ts` (Node.js actions only with "use node")
- Split into `cryptographicQrInternal.ts` (Convex runtime for queries/mutations)
- Created `clientQr.ts` (Convex runtime for client-facing query)

### QR Data Format
```
dcwlt://pay?u=USER_ID&k=TIME_KEY&s=SIGNATURE
```
- `u`: User's Privy ID (URL encoded)
- `k`: TOTP time-based key (60-second windows)
- `s`: HMAC-SHA256 signature of `userId:timeKey`

## Security Notes

1. **Server secret NEVER exposed to client**: Secret is fetched via Convex query
2. **User authentication required**: Query validates identity before returning secrets
3. **Authorization check**: User can only request their own QR secret
4. **Time-limited validity**: QR codes expire after 5 minutes with auto-refresh
