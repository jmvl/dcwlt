# Phase 04.2-01: User App Payment Workflow UX Improvements

**Objective:** Streamline the payment confirmation flow with mobile-responsive design and remove unnecessary friction points.

## Context

The current payment confirmation flow has several UX issues that create friction:

1. **3-second countdown timer** - adds unnecessary delay after user has already intentionally scanned a QR code
2. **"Unknown Merchant" display** - shows placeholder when merchant name is available in Convex
3. **Small side-by-side buttons** - not optimized for mobile touch targets (should be stacked on small screens)
4. **Privy action sheet** - an intermediate step during signing (may be necessary security UX)
5. **Privy "Transaction Signed" close button** - extra UI element that auto-dismisses anyway

## Discovery Results

### Current Implementation

**PaymentConfirmation Component** (`pwa/app/components/PaymentConfirmation.tsx`):
- Lines 89-108: 3-second countdown timer with `canConfirm` state
- Line 112: `merchantLabel = label || 'Unknown Merchant'` - uses URL parameter if present
- Lines 179-202: Side-by-side buttons with `flex-1` (responsive but not stacked on mobile)
- The component receives `label` prop but it's not populated from merchant lookup

**Confirm Payment Page** (`pwa/app/confirm-payment/page.tsx`):
- Lines 38-42: Already queries `getMerchantByWallet` for merchant data
- Line 46: `merchantId` extracted but `businessName` not passed to PaymentConfirmation
- Line 280: `label` prop passed directly from URL parameter (not from merchant lookup)

**Merchant Schema** (`pwa/convex/schema.ts`):
- `merchants` table has `businessName` field (line 52)

**Convex Query** (`pwa/convex/merchants.ts`):
- Lines 85-101: `getMerchantByWallet` returns full merchant object including `businessName`

### Privy Integration Constraints

The Privy action sheet (step 4 in user's list) is a **security feature** that cannot be disabled:
- User must explicitly authorize the transaction in Privy's UI
- This is part of Privy's embedded wallet security model
- The "Transaction Signed" close button (step 5) is part of Privy's modal and cannot be customized

### Mobile Touch Target Best Practices

- **Minimum 44x44px** for touch targets (Apple HIG)
- **Stack vertically** on small screens (< 640px) for better thumb reach
- **Primary action bottom** (Confirm Payment) for easy access

## Tasks

### Task 1: Remove Countdown Timer

**File:** `pwa/app/components/PaymentConfirmation.tsx`

**Changes:**
- Remove `countdown` state and `canConfirm` state (lines 89-90)
- Remove `useEffect` for countdown timer (lines 93-108)
- Remove countdown display section (lines 169-176)
- Remove `disabled={!canConfirm || loading}` from Confirm button (line 190) → `disabled={loading}`
- Update confirm button to always be enabled (unless loading)

**Rationale:** Users have already taken intentional action by scanning QR code. Countdown adds unnecessary friction.

### Task 2: Display Merchant Name from Convex Lookup

**File:** `pwa/app/confirm-payment/page.tsx`

**Changes:**
- Extract `businessName` from merchant query result (after line 46)
- Pass `businessName` to PaymentConfirmation as `label` prop (line 280)
- Fallback logic: `label={merchant?.businessName || searchParams.get('label') || undefined}`
- Update PaymentConfirmation props type to include merchant data if needed

**Rationale:** Merchant name is available in Convex. Display it instead of "Unknown Merchant".

### Task 3: Mobile-Responsive Button Layout

**File:** `pwa/app/components/PaymentConfirmation.tsx`

**Changes:**
- Update button container (line 179): Add responsive classes
  - Current: `className="flex gap-3"`
  - New: `className="flex flex-col sm:flex-row gap-3"` (stack on mobile, side-by-side on sm+)
- Update button sizing for better touch targets:
  - Current: `py-3 px-4` (12px vertical, 16px horizontal)
  - New: `py-4 px-6 text-base` (16px vertical, 24px horizontal, larger text)
- Ensure minimum 44px height on touch targets

**Rationale:** Mobile UX best practices require stacked buttons and larger touch targets.

### Task 4: Document Privy Action Sheet Behavior

**File:** `.planning/phases/04.2-user-app-ux/04.2-01-SUMMARY.md` (post-implementation)

**Action:**
- Add note to STATE.md decisions: "Privy action sheet is necessary security UX and cannot be disabled"
- The action sheet appears during `signTransaction()` call in `usePayment.ts` (line 106)
- This is expected behavior for non-custodial wallet security

**Rationale:** User asked if we can avoid this step. Answer: No, it's a security feature of Privy embedded wallets.

### Task 5: Investigate Privy Modal Close Button

**Investigation:**
- Check if Privy provider config has modal customization options
- The "Transaction Signed" modal is part of Privy's internal UI
- Most likely: Cannot be removed (security UX requirement)

**Expected Outcome:**
- Document that close button is part of Privy's modal and cannot be customized
- If customization is possible via Privy config, implement it
