## Decisions Made

1. **Composite index for uniqueness** - Added `by_event_merchant` index on (eventId, merchantId) to enforce that one merchant can only be assigned once per event. This prevents duplicate assignments at the database level.

2. **Booth number as required field** - Booth number is a required string field in the junction table (not optional). This ensures every merchant assignment has a physical location mapping for event operations.

3. **Approved merchant validation** - The assignMerchantToEvent mutation validates that merchant.status === "approved" before creating assignment. This prevents pending/rejected merchants from being assigned to events.

4. **Join queries in backend** - getEventAssignments and getMerchantAssignments queries fetch related entity details (merchant or event) and return complete data. This reduces client-side data fetching and provides sorted results (by booth number for events, by date for merchants).

5. **Two-panel master-detail UI** - Following established admin UI pattern from /admin/events, the assignments page uses left panel for entity selection (events) and right panel for related items (merchant assignments). This provides efficient workflow for managing many-to-many relationships.
