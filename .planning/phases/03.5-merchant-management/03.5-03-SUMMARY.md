## Decisions Made

1. **Events table supports both predefined and custom types** - Type field stores standard categories (Concert, Sports, Festival) while customType field stores custom category names when type="Custom". This provides structure while maintaining flexibility.

2. **Date stored as ISO string** - Using ISO date strings (e.g., "2026-07-15") instead of timestamps for better readability and easier date manipulation in UI. No validation that date is in future to allow creating past events for testing.

3. **Color-coded type badges** - Each predefined type has a distinct color (Concert=blue, Sports=green, Festival=purple, Custom=gray) for quick visual scanning in the event list.

4. **Conditional custom type field** - Custom type input only appears when "Custom" is selected in the type dropdown, keeping the form clean while guiding user input.

5. **Date sorting in getEvents query** - Events returned sorted chronologically by date (earliest first) to help administrators see upcoming events.
