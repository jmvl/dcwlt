## Decisions Made

1. **Admin access control via email domain** - Used `@dcwlt.com` email check for admin authorization, consistent with existing merchant approval workflow

2. **Privy email type casting** - Cast Privy's `Email` type to `string` to use `endsWith()` method for domain checking. The existing admin page had the same pattern but wasn't type-safe, so fixed it in both locations

3. **Convex mutation pattern** - Convex mutations are called directly as functions (`await mutation(args)`), not with `.mutate()` or `.mutateAsync()` methods. Fixed existing admin page that was using incorrect pattern

4. **Lucide icon naming conflict** - When importing both `Link` icon and Next.js `Link` component, renamed icon import to `LinkIcon` to avoid collision

5. **Low balance threshold** - Set 10 EVT as the warning threshold for merchant wallet balances, with yellow highlighting and warning icon in dashboard

6. **Wallet data joining** - Dashboard joins `merchants` and `wallets` tables on `walletAddress` to display merchant balances, since there's no direct foreign key relationship

## Issues Encountered

- **Privy Email type incompatibility** - Privy's custom `Email` type doesn't support string methods like `endsWith()`. Resolved by type casting, which is a safe operation since Email is always a string at runtime.

- **Convex mutation API confusion** - The Convex React integration has changed over time. Old documentation shows `.mutate()` method, but current API calls mutations directly. Verified by checking working code in events page.

- **Lucide icon prop validation** - Lucide React has strict TypeScript types that don't accept arbitrary props like `title`. Icons use semantic HTML titles via aria-label instead.
