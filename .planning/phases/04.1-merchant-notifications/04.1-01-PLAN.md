## Technical Context

**Convex Real-Time Subscriptions**:
- `useQuery` from `convex/react` automatically creates WebSocket subscription
- Subscription persists as long as query parameters remain stable (reference equality)
- When parameters change, query unsubscribes and resubscribes with new parameters
- During resubscription, UI shows stale data or loading state

**Filter Trade-off**:
- Server-side filtering: Efficient data transfer, but causes resubscription on filter change
- Client-side filtering: Stable subscription, but transfers more data initially
- **Decision**: For merchant transaction volume (estimated <1000/merchant/event), client-side filtering is acceptable

**Multi-Device Support**:
- Each merchant device subscribes independently to same query
- Convex broadcasts database change to all subscribed clients simultaneously
- No additional backend logic required for multi-device sync

## Task 1: Create unfiltered live transaction query

**File**: `pwa/convex/transactions.ts`

**Action**: Add `listLiveMerchantTransactions` query

```typescript
export const listLiveMerchantTransactions = query({
  args: {
    merchantId: v.id("merchants"),
  },
  handler: async (ctx, args) => {
    // Query all transactions for this merchant, no filters
    const transactions = await ctx.db
      .query("transactions")
      .withIndex("byMerchantByTime", (q) => q.eq("merchantId", args.merchantId))
      .order("desc")
      .take(100); // Limit to last 100 for performance

    // Fetch item names for display
    const transactionsWithItems = await Promise.all(
      transactions.map(async (tx) => {
        const item = await ctx.db.get(tx.itemId);
        return {
          ...tx,
          itemName: item?.name || "Unknown Item",
        };
      })
    );

    return transactionsWithItems;
  },
});
```

**Why this approach**:
- Single parameter (merchantId) means subscription never resubscribes
- `order("desc")` puts newest transactions first
- `take(100)` limits data transfer while covering reasonable event volume
- Joins with items table for display (same pattern as existing query)

**Verification**:
- Query compiles without errors
- Returns transactions sorted newest-first
- No TypeScript errors on merchantId type

## Task 2: Create live transactions hook with client-side filtering

**File**: `pwa/app/hooks/useMerchantLiveTransactions.ts` (new file)

**Action**: Create custom hook

```typescript
"use client";

import { useQuery } from "convex/react";
import { api } from "@/convex/_generated/api";
import { useMemo, useState, useEffect } from "react";

interface FilterOptions {
  dateRange?: "today" | "week" | "month" | "all";
  searchWallet?: string;
}

export function useMerchantLiveTransactions(
  merchantId: string,
  filters: FilterOptions
) {
  // Stable subscription to all transactions
  const allTransactions = useQuery(api.transactions.listLiveMerchantTransactions, {
    merchantId: merchantId as any,
  });

  // Track previous transaction count for new payment detection
  const [prevCount, setPrevCount] = useState(0);
  const isNewPayment = allTransactions && allTransactions.length > prevCount;

  useEffect(() => {
    if (allTransactions) {
      setPrevCount(allTransactions.length);
    }
  }, [allTransactions]);

  // Client-side filtering
  const filteredTransactions = useMemo(() => {
    if (!allTransactions) return undefined;

    let filtered = [...allTransactions];

    // Apply date range filter
    if (filters.dateRange && filters.dateRange !== "all") {
      const now = Date.now();
      const cutoff = {
        today: now - 24 * 60 * 60 * 1000,
        week: now - 7 * 24 * 60 * 60 * 1000,
        month: now - 30 * 24 * 60 * 60 * 1000,
      }[filters.dateRange];

      filtered = filtered.filter((tx) => tx.timestamp >= cutoff);
    }

    // Apply wallet search filter
    if (filters.searchWallet) {
      filtered = filtered.filter((tx) =>
        tx.customerWallet.toLowerCase().includes(filters.searchWallet!.toLowerCase())
      );
    }

    return filtered;
  }, [allTransactions, filters.dateRange, filters.searchWallet]);

  return {
    transactions: filteredTransactions,
    allTransactions,
    isLoading: allTransactions === undefined,
    isNewPayment,
  };
}
```

**Why this approach**:
- `useQuery` parameters never change (stable merchantId reference)
- Client-side filtering with `useMemo` prevents unnecessary re-renders
- `isNewPayment` flag detects new transactions for toast notifications
- Returns both filtered (for display) and all transactions (for stats)

**Verification**:
- Hook compiles without TypeScript errors
- Filter logic matches existing `listMerchantTransactions` behavior
- `isNewPayment` correctly triggers when new transaction arrives

**File**: `pwa/app/merchant/sales/page.tsx`

**Action**: Replace `useQuery` with `useMerchantLiveTransactions`, add toast notification

**Changes**:

2. Replace existing transaction query with hook

4. Update stats calculation to use `allTransactions` (include all-time data)

```typescript
// Inside SalesPage component:

// Use live hook instead of direct useQuery
const { transactions, allTransactions, isLoading, isNewPayment } =
  useMerchantLiveTransactions(merchant!._id, { dateRange, searchWallet: debouncedSearch });

// Show toast notification for new payment
useEffect(() => {
  if (isNewPayment && transactions && transactions.length > 0) {
    const newTx = transactions[0]; // Most recent transaction
    toast.success(`New payment: ${newTx.itemName} - ${newTx.amount} EVT`, {
      duration: 5000,
      position: "top-center",
    });
  }
}, [isNewPayment, transactions]);

// Update stats to use allTransactions (unfiltered) for accurate totals
const stats = useMemo(() => {
  if (!allTransactions) return null;

  const confirmed = allTransactions.filter((tx) => tx.status === "confirmed");

  return {
    totalSales: confirmed.reduce((sum, tx) => sum + tx.amount, 0),
    transactionCount: confirmed.length,
    averageAmount: confirmed.length > 0
      ? confirmed.reduce((sum, tx) => sum + tx.amount, 0) / confirmed.length
      : 0,
    todaySales: confirmed
      .filter((tx) => tx.timestamp >= Date.now() - 24 * 60 * 60 * 1000)
      .reduce((sum, tx) => sum + tx.amount, 0),
  };
}, [allTransactions]);
```

**Why this approach**:
- Maintains existing filter UI (date buttons, search input)
- Toast notification provides immediate feedback
- Stats calculated from all transactions (not filtered) for accurate totals
- No changes to table rendering logic

**Verification**:
- Page compiles without errors
- Toast appears when new transaction arrives
- Filters still work correctly
- Stats show accurate all-time totals
