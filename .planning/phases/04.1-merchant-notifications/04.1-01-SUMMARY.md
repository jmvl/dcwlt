## Decisions Made

**Decision 92: Client-side filtering preserves stable WebSocket subscription**
- Rationale: Server-side filtering causes Convex to unsubscribe/resubscribe when parameters change, creating flicker and missing real-time updates during filter transitions
- Implementation: Unfiltered query with stable parameters + client-side filtering via useMemo
- Trade-off: Transfers more data initially (100 transactions vs filtered subset), but acceptable for merchant transaction volume

**Decision 93: Toast notifications use sonner library**
- Rationale: Modern, lightweight toast library compatible with React 19 and Next.js 16, better than alternatives (react-hot-toast unmaintained, react-toastify heavy)
- Implementation: Toaster component in root layout with custom styling matching merchant portal theme (#1a2f38 background, #13a4ec border)
- Duration: 5 seconds, top-center position

**Decision 94: Limited live query to last 100 transactions**
- Rationale: Balances performance with reasonable event volume coverage - most events won't exceed 100 transactions per merchant
- Implementation: `.take(100)` on indexed query with `.order("desc")` for newest-first
- Alternative considered: Unlimited query (rejected - could impact performance on high-volume events)
