# Phase 04.4: Dashboard Visual Refactor

**Status:** INSERTED PHASE
**Type:** Visual Polish & UX Enhancement
**Triggered by:** Gap analysis after Phase 4.3 completion

## Context

Phase 4.3 (User Dashboard UX) delivered functional dashboard components with correct data flow and real-time updates. However, visual review against the design reference revealed significant gaps in visual fidelity, polish, and user experience.

## Problem Statement

The current dashboard implementation (Phase 4.3) is **functionally complete** but **visually underdeveloped**:

- Grade: B- (Functional but lacks polish)
- Target Grade: A- (Premium, production-ready)

**Critical Issues:**
1. Balance text size: 36px → 56px (hero element undersized)
2. Balance card padding: 20px → 32px (feels cramped)
3. Color system: No systematic palette (scattered ad-hoc colors)
4. Balance gradient: External PNG dependency (should be pure CSS)
5. Elevation system: Missing shadows (flat appearance)

## Design Reference

Target design is captured in:
- `.planning/research/uix-user-dashboard/code.html` - Full HTML reference
- `.planning/research/uix-user-dashboard/screen.png` - Visual mockup

Key design characteristics:
- Dark theme with navy background (#0A1229)
- Vibrant cyan primary color (#00BCD4)
- Extra-large balance display (56px ExtraBold)
- CSS-only gradients (no image dependencies)
- Shadow-based elevation (no visible borders)
- 8px spacing system with 32px balance card padding

## Success Criteria

After this phase, the dashboard should:

1. Match design reference visual fidelity (95%+)
2. Use systematic color palette from DESIGN_SYSTEM.md
3. Have proper elevation via shadows (no flat appearance)
4. Display balance as hero element (56px, proper padding)
5. All spacing follow 8px grid system
6. Pure CSS implementation (no external image dependencies)
7. Touch targets meet accessibility minimums (44px)

## Dependencies

- No new backend changes (pure frontend refactor)
