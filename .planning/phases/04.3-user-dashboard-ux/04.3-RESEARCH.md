# Phase 4.3: User Dashboard UX - Research

**Researched:** 2026-01-20
**Domain:** Mobile PWA Dashboard UI/UX with Next.js, Tailwind CSS, Convex
**Confidence:** HIGH

## Summary

This phase involves building a mobile-first user dashboard for a crypto wallet PWA. The mockup shows a modern dark-themed wallet interface with gradient balance card, action buttons, transaction list, and bottom navigation with elevated center scan button. The implementation requires integrating existing Privy auth, Solana balance display, and Convex real-time transactions into a cohesive mobile experience.

**Primary recommendation:** Build dashboard as single-page app with component-based architecture using existing BalanceDisplay component, add Convex transactions query with real-time subscription, implement bottom navigation with elevated center button pattern, ensure 44px minimum touch targets for accessibility.

### Pattern 1: Component-Based Dashboard with Real-Time Data

**What:** Break dashboard into modular components, each responsible for specific data fetching and display using Convex's real-time useQuery hook.

**When to use:** For all dashboard sections that need real-time updates (balance, transactions).

**Example:**
```typescript
// hooks/useUserTransactions.ts
import { useQuery } from 'convex/react';
import { api } from '@/convex/_generated/api';

/**
 * Real-time hook for user's transaction history
 * Automatically subscribes to updates in Convex transactions table
 *
 * @param walletAddress - User's Solana wallet address
 * @returns Last 5 transactions, newest first
 */
export function useUserTransactions(walletAddress?: string) {
  return useQuery(
    api.transactions.listUserTransactions,
    walletAddress ? { walletAddress, limit: 5 } : "skip"
  );
}

// Usage in TransactionList.tsx
export function TransactionList({ walletAddress }: Props) {
  const transactions = useUserTransactions(walletAddress);

  if (!transactions) return <LoadingSkeleton />;

  return (
    <div className="flex flex-col gap-3">
      {transactions.map(tx => (
        <TransactionItem key={tx._id} transaction={tx} />
      ))}
    </div>
  );
}
```

**Source:** [Convex React Documentation](https://docs.convex.dev/client/react) - useQuery automatically subscribes to data changes

### Pattern 4: Transaction List with Color-Coded Amounts

**What:** List of recent transactions with icon, merchant name, timestamp, amount (color-coded by type), and category label.

**When to use:** Displaying transaction history in wallet/dashboard interfaces.

**Example:**
```typescript
// components/TransactionItem.tsx
interface Transaction {
  _id: string;
  itemName: string;
  timestamp: number;
  amount: number;
  category?: string;
}

export function TransactionItem({ transaction }: { transaction: Transaction }) {
  const isExpense = transaction.amount < 0;
  const amountColor = isExpense ? 'text-white' : 'text-primary';

  // Format timestamp relative to now
  const timeAgo = formatTimeAgo(transaction.timestamp);

  return (
    <div className="flex items-center gap-4 bg-[#1c2a31]/40 rounded-2xl px-4 min-h-[80px] py-2 justify-between border border-white/5">
      <div className="flex items-center gap-4">
        <div className="text-white flex items-center justify-center rounded-xl bg-[#283339] shrink-0 size-12">
          <span className="material-symbols-outlined text-orange-400">shopping_bag</span>
        </div>
        <div className="flex flex-col justify-center">
          <p className="text-white text-base font-bold leading-normal">{transaction.itemName}</p>
          <p className="text-[#9db0b9] text-xs font-medium">{timeAgo}</p>
        </div>
      </div>
      <div className="shrink-0 text-right">
        <p className={`${amountColor} text-base font-bold`}>
          {transaction.amount > 0 ? '+' : ''}{transaction.amount.toFixed(2)} EVT
        </p>
        {transaction.category && (
          <p className="text-[#9db0b9] text-[10px] uppercase font-bold tracking-wider">
            {transaction.category}
          </p>
        )}
      </div>
    </div>
  );
}

// Helper function for relative time formatting
function formatTimeAgo(timestamp: number): string {
  const now = Date.now();
  const diff = now - timestamp;

  if (diff < 60000) return 'Just now';
  if (diff < 3600000) return `${Math.floor(diff / 60000)}m ago`;
  if (diff < 86400000) return `Today, ${new Date(timestamp).toLocaleTimeString([], { hour: '2-digit', minute: '2-digit' })}`;
  if (diff < 172800000) return 'Yesterday';

  return new Date(timestamp).toLocaleDateString();
}
```

**Source:** [Mobile wallet app transaction history UI patterns](https://designcode.io/quick-apps-figma-wallet1/) - Wallet transaction screen design patterns

### Anti-Patterns to Avoid

- **Hardcoded transaction data:** Always use Convex real-time queries for live updates
- **Insufficient touch targets:** Buttons must be minimum 44×44px (iOS) or 48×48dp (Android)
- **Missing safe area insets:** Bottom nav must use `env(safe-area-inset-bottom)` for notched devices
- **Inconsistent icon libraries:** Stick to Material Symbols Outlined as specified in STATE.md
- **No loading states:** Always show skeleton/loading while Convex queries fetch initial data
- **Ignoring accessibility:** Use proper aria-labels on icon-only buttons

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Real-time data subscriptions | Manual WebSocket polling | Convex `useQuery` | Automatic reactivity, no manual connection management |
| Time formatting | Custom date math | `date-fns` or `Intl.DateTimeFormat` | Handles edge cases, localization, timezone issues |
| Safe area handling | Hardcoded padding values | CSS `env(safe-area-inset-*)` | Works across all notched devices (iPhone X+, Android) |
| Icon system | SVG files or icon fonts | Material Symbols Outlined | 2,500+ icons, variable font (weight, fill, optical size) |
| Touch target sizing | Manual pixel values | Tailwind utilities (`size-14`, `min-h-[44px]`) | Consistent across app, follows platform guidelines |

**Key insight:** Convex's real-time sync engine eliminates need for manual WebSocket setup, polling, or state management complexity. The `useQuery` hook handles all subscription logic automatically.

## Common Pitfalls

### Pitfall 1: Missing Convex Index for User Transactions

**What goes wrong:** Querying transactions by `customerWallet` without index causes full table scan, slow performance as transactions grow.

**Why it happens:** Current schema only has `byMerchant` and `byMerchantByTime` indexes. No index for customer wallet lookups.

**How to avoid:** Add `byCustomerByTime` index to Convex schema before implementing dashboard:

```typescript
// convex/schema.ts - transactions table
transactions: defineTable({
  // ... existing fields
})
  .index("byMerchant", ["merchantId"])
  .index("byMerchantByTime", ["merchantId", "timestamp"])
  .index("byCustomerByTime", ["customerWallet", "timestamp"]), // ADD THIS
```

**Warning signs:** Slow initial load, Convex console shows full table scans, queries time out.

### Pitfall 2: Bottom Navigation Overlapping Content

**What goes wrong:** Fixed bottom nav covers last transaction in list or "See All" button becomes unclickable.

**Why it happens:** Forgetting to add bottom padding to main content area equal to nav height.

**How to avoid:** Add `pb-24` (96px) or `pb-safe-bottom` to main container:

```typescript
<main className="flex-1 overflow-y-auto pb-24">
  {/* Transaction list with padding for bottom nav */}
</main>
```

**Warning signs:** User can't scroll to last item, buttons at bottom don't respond to taps.

### Pitfall 3: Touch Targets Too Small on Mobile

**What goes wrong:** Users accidentally tap wrong buttons, struggle with small icon buttons.

**Why it happens:** Designing for desktop first, not considering finger size (average 11mm / 44px).

**How to avoid:** Ensure ALL interactive elements meet minimum sizes:

```css
/* Minimum touch targets per platform guidelines */
WCAG 2.5.8:  24×24px (minimum)
iOS HIG:      44×44px (recommended)
Android MD:   48×48dp (recommended)

/* Use Tailwind utilities */
<button className="min-h-[44px] min-w-[44px]">...</button>
<button className="size-14">...</button> {/* 56px - even better */}
```

**Warning signs:** Users complain about "fat finger" mistakes, analytics shows accidental clicks.

### Pitfall 4: Safe Area Insets Ignored on Notched Devices

**What goes wrong:** Bottom navigation hidden by iPhone home indicator or Android gesture bar.

**Why it happens:** Using fixed positioning without `env(safe-area-inset-bottom)`.

**How to avoid:** Use existing `.safe-area-inset-bottom` utility from globals.css:

```typescript
<nav className="fixed bottom-0 left-0 right-0 bg-[#1c2a31] safe-area-inset-bottom">
  {/* Nav content */}
</nav>
```

**Warning signs:** UI elements cut off on iPhone X+, Galaxy S10+, Pixel 3+ devices.

### Pitfall 5: Balance Display Jumps During Loading

**What goes wrong:** Balance card appears empty, then suddenly populates, causing layout shift.

**Why it happens:** Not accounting for loading state, or balance value changes from placeholder to actual value.

**How to avoid:** Show skeleton loader or maintain consistent height during fetch:

```typescript
{isLoading ? (
  <div className="h-[220px] flex items-center justify-center">
    <div className="animate-pulse bg-[#1c2a31] rounded-2xl h-full w-full" />
  </div>
) : (
  <BalanceCard balance={balance} />
)}
```

**Warning signs:** Layout shifts when data loads, CLS (Cumulative Layout Shift) warnings in Lighthouse.

### Convex Real-Time Transaction Query

```typescript
// convex/transactions.ts - Add to existing file
export const listUserTransactions = query({
  args: {
    walletAddress: v.string(),
    limit: v.optional(v.number()),
  },
  handler: async (ctx, args) => {
    // Query transactions by customer wallet (requires index)
    const transactions = await ctx.db
      .query("transactions")
      .withIndex("byCustomerByTime", (q) =>
        q.eq("customerWallet", args.walletAddress)
      )
      .order("desc")
      .take(args.limit ?? 5);

    // Fetch item names for display
    const transactionsWithItems = await Promise.all(
      transactions.map(async (tx) => {
        const item = await ctx.db.get(tx.itemId);
        return {
          ...tx,
          itemName: item?.name || "Unknown Item",
        };
      })
    );

    return transactionsWithItems;
  },
});
```

### Time Formatting Utility

```typescript
// utils/formatTime.ts
export function formatTransactionTime(timestamp: number): string {
  const now = Date.now();
  const diff = now - timestamp;
  const date = new Date(timestamp);

  // Less than 1 minute
  if (diff < 60000) return 'Just now';

  // Less than 1 hour
  if (diff < 3600000) {
    const mins = Math.floor(diff / 60000);
    return `${mins}m ago`;
  }

  // Today
  if (diff < 86400000) {
    return `Today, ${date.toLocaleTimeString([], { hour: '2-digit', minute: '2-digit' })}`;
  }

  // Yesterday
  if (diff < 172800000) {
    return `Yesterday, ${date.toLocaleTimeString([], { hour: '2-digit', minute: '2-digit' })}`;
  }

  // Older than 2 days
  return date.toLocaleDateString([], { month: 'short', day: 'numeric' });
}
```

**Source:** Standard relative time formatting pattern used in mobile apps

## State of the Art

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| Polling/WebSocket for real-time | Convex useQuery auto-subscription | 2024-2025 | Zero-config real-time, no manual connection management |

**Deprecated/outdated:**
- **Manual WebSocket implementations:** Convex handles this transparently
- **Fixed pixel padding for notched devices:** Use `env()` CSS variables instead
- **Icon fonts with separate files:** Variable fonts like Material Symbols are more performant
